# Бесплатный хостинг: Vercel + Supabase + GitHub Actions

## Контекст и решения пользователя (2026-11-07)
- Бюджета нет → только бесплатные тарифы.
- Репозиторий `github.com/Baiqa/hotaru` уже существует и **публичный** (проверено через API). Запушен только первый коммит, локально ещё 7 коммитов + незакоммиченный Этап 4.
- Аудит истории перед пушем: секретов нет (пароль в `worker/.env.example` — заглушка длиной 15 симв., реальный .env-пароль длиной 16 и не совпадает). `sample_export.json` содержит только заголовки/лиды/источники, не тела статей.
- Платный Gemini — «когда все функции будут работать».
- Казахские источники не нужны. Авторизация допустима, но отдельной задачей позже.

## Архитектура
| Часть | Где | Как |
|---|---|---|
| Фронт `web/` | Vercel Hobby | Импорт репозитория, Root Directory = `web`, env `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY` |
| БД | Supabase free (как сейчас) | Регулярные записи воркера не дают проекту уснуть |
| Воркер `worker/` | GitHub Actions по расписанию | Секреты репозитория: `DATABASE_URL`, `GOOGLE_API_KEY`, `CONTACT_EMAIL` |

## Три workflow (с `concurrency`, чтобы запуски одной группы не пересекались)
1. `collect.yml`, каждые 30 мин: collect → extract-entities → embed-articles → cluster-events.
2. `llm.yml`, раз в час (со сдвигом): extract-claims → embed-claims → group-claims → synthesize. Уже защищены `quota.has_quota`, при исчерпанной квоте выходят за секунды.
3. `maintenance.yml`: merge-events (час), assign-stories (час), split-events (сутки), fetch-metrics (сутки), monitor (сутки).

Установка: `uv sync` + кеш uv; spaCy-модели ставятся из прямых URL в pyproject, кешируются.

## Шаги
1. Проверить и закоммитить Этап 4 (build, lint, ручной прогон assign-stories, /stories на телефоне).
2. `git push` (после явного подтверждения).
3. Написать 3 workflow-файла в `.github/workflows/`, прогнать каждый вручную через `workflow_dispatch`.
4. Пользователь сам добавляет secrets в GitHub (я ключи не трогаю).
5. Пользователь подключает репозиторий к Vercel; я проверяю деплой и страницы.
6. Через 1–2 суток проверить мониторинг (`hotaru-monitor`): коллектор дал статьи, дедуп-дубликатов нет.

## Известные риски (проверить, не считать установленными)
- Cron в Actions может сдвигаться на минуты; не гарантирует точность.
- Публичные логи workflow видны всем — следить, чтобы воркер не печатал лишнего.
- Запланированные workflow в публичных репозиториях отключаются после долгой неактивности репозитория (по моим знаниям, ~60 дней) — перепроверить в документации GitHub.
- Vercel Hobby рассчитан на некоммерческое использование.
- Хватит ли RAM у раннера для spaCy — выяснится на первом прогоне.

## Проверка
- Каждый workflow завершается успешно вручную; `articles` растёт без дублей по `canonical_url`.
- Vercel-страницы `/`, `/events/[id]`, `/stories/[id]` открываются с продакшен-URL и показывают живые данные.
- Через сутки: `hotaru-monitor` без алертов «0 статей за 24 часа».
