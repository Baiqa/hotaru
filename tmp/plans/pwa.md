## Предлагаемые изменения

### 1. Манифест и иконки
- `src/app/manifest.ts`: name «Hotaru», short_name «Hotaru», `display: standalone`, `start_url: "/"`, `lang: "ru"`, цвета фона/темы, иконки 192 и 512 (одна `any` и одна `maskable`).
- Иконки через `src/app/icon.tsx` + `apple-icon.tsx` (`ImageResponse`, генерируются при сборке, без ручных PNG): тёмный квадрат с жёлто-зелёной точкой («светлячок»). Дизайн минимальный; если хотите свой логотип — подставлю файл.
- Проверка: `/manifest.webmanifest` отдаёт валидный JSON, иконки отвечают 200 и `image/png` нужных размеров.

### 2. Service Worker (`public/sw.js`, без внешних библиотек)
- Регистрация: клиентский компонент в `layout.tsx`, только в production; `scope: "/"`; заголовки `Cache-Control: no-cache` и `Service-Worker-Allowed` для `/sw.js` через `headers()` в `next.config.ts`.
- Стратегии:
  - `/_next/static/*` и иконки: cache-first (файлы с хешем в имени).
  - Навигации (HTML) по `/`, `/events/*`, `/stories/*`, `/articles/*`: network-first с таймаутом 4 с, ответ кладётся в кеш; при отсутствии сети отдаётся кеш, иначе страница `/offline`.
  - RSC-запросы мягкой навигации и все не-GET запросы: не перехватываются. Без сети Next сам откатывается на полную навигацию, её подхватит SW.
- Что попадает в кеш: страницы, которые пользователь открыл. Чтобы это работало и при мягкой навигации (Next не делает HTML-запрос), добавляю в клиентский компонент отправку SW сообщения `{type:"cache", url}` на каждую смену `usePathname()`; SW сам скачивает HTML и кладёт в кеш.
- Лимит: последние 40 страниц (вытеснение старых), кеш версионирован (`hotaru-pages-v1`), старые версии удаляются на `activate`, `skipWaiting` + `clients.claim`.
- Что не кешируется: ответы не 200, страницы с `Cache-Control: no-store` пользовательских данных (их пока нет).
- Риск: пользователь видит старую страницу, если сеть медленная (>4 с). Это осознанный компромисс; на странице появится метка «Сохранённая версия от …» (см. п. 3).

### 3. Оффлайн-индикатор и страница `/offline`
- Маленькая полоса сверху «Нет сети. Показаны сохранённые материалы» (клиентский компонент на `navigator.onLine`, события `online`/`offline`).
- `src/app/offline/page.tsx`: статическая страница «Эта страница не сохранена. Откройте её, пока есть сеть.» со ссылкой на главную; кладётся в кеш на `install`.
- Экспериментальный `experimental.useOffline` из Next не включаю: он помечен как experimental и меняет поведение навигации.

### 4. Safe area и viewport
- `export const viewport` в `layout.tsx`: `viewportFit: "cover"`, `themeColor` для светлой и тёмной темы.
- Шапка и основной контент получают отступы `env(safe-area-inset-top/bottom/left/right)`.

### 5. Скелетоны
- Добавить `loading.tsx` только там, где это не ломает 404: страница сравнения `/events/[id]/compare` не имеет `notFound()`-ветки? Проверю при реализации; если имеет — оставляю без скелетона и записываю причину. Остальные страницы не меняю.

### 6. Переходы между экранами и «назад»
- Лёгкий CSS-fade при смене страницы (`@keyframes` на `main`, отключается при `prefers-reduced-motion`).
- View Transitions API (`experimental.viewTransition`) не включаю: экспериментальный флаг. Жест «назад» остаётся браузерным: на Android и в standalone он работает по истории браузера. На страницах уже есть ссылки «← На главную» / «← К событию».

## Критерии готовности (проверяются)
1. `npm run build` и `npm run lint` проходят.
2. `/manifest.webmanifest` валиден, иконки 192/512 отвечают 200 `image/png`.
3. В production-режиме (`npm start`) SW регистрируется (`navigator.serviceWorker.getRegistrations()`), кеш `hotaru-pages-v1` существует.
4. Оффлайн-проверка: открыть главную и 2 события при работающей сети, остановить сервер, перезагрузить страницы: они открываются из кеша; не открытая страница показывает `/offline`.
5. 404 по-прежнему настоящий 404 (`/events/00000000-…` → 404), в том числе после добавления SW.
6. Lighthouse PWA / installability в браузерной панели (если доступно) или проверка критериев установки вручную (manifest + SW + HTTPS).
7. На Vercel после деплоя: SW регистрируется на https://hotaru-seven.vercel.app, в логах нет ошибок.
