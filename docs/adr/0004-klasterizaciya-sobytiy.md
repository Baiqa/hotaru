# ADR-0004: Кластеризация событий: скоринг, два порога, LLM для серой зоны, слияние и разделение

**Статус:** Принято, есть открытые проблемы качества
**Дата:** 2026-09-27 (решение), калибровки 2026-10-16, 2026-11-10, 2026-11-16
**Принимал:** владелец проекта

## Контекст

Несколько изданий пишут об одном событии; нужно собрать их в одну карточку и не склеить разное (два одинаковых заседания в разные
даты, компании-тёзки, длинный сюжет). Один порог не может быть одновременно строгим и мягким, поэтому спецификация (§3.3) делит
задачу на два уровня: **событие** (один факт реальности, часы–дни) и **сюжет** ([ADR-0005](0005-syuzhety-po-poslednim-uchastnikam.md)).

## Решение

Инкрементальный алгоритм, статья за статьёй:

1. **Кандидаты:** топ-50 по `pgvector` среди статей окна 5 суток, делящих хотя бы одну сущность.
2. **Скор** (четыре сигнала): IDF-Жаккар сущностей 0.35, совпадение чисел и дат 0.20 (в БД и коде называется `tokens_jaccard`),
   косинус эмбеддингов 0.30, близость по времени 0.15 (полураспад 24 ч). Веса взяты из спецификации и **не пересчитывались**.
3. **Решение по двум порогам:** выше `UPPER_THRESHOLD = 0.75` присоединить, ниже `LOWER_THRESHOLD = 0.38` создать новое событие,
   между ними (серая зона) спросить LLM с ответом `same | related | different`. Присоединение только по `same`; `related` на этом
   уровне трактуется как `different`. Пробуется до `CANDIDATE_TRIES = 2` лучших кандидатов.
4. **Жёсткий лимит события:** 72 часа и 40 статей (событие — факт, а не цепочка).
5. **Слияние раз в час:** косинус центроидов ≥ 0.85 **и** хотя бы одна сущность, общая для большинства статей обоих событий.
   **Разделение раз в сутки** по внутренней связности. Старые ссылки не умирают благодаря `events.canonical_id`.

Ответы LLM кешируются по паре статей (`gray_zone_verdicts`) вместе с сигналами, по которым пара попала в серую зону.

## Рассмотренные варианты и как менялись параметры

| Параметр | Было | Стало | Почему |
|---|---|---|---|
| Нижний порог | 0.45 (спецификация) | 0.40, затем 0.38 | Пара про тайфун Dujuan (одно событие) имела скор 0.413 и не доходила до LLM; затем по B-Cubed-разметке 0.38 чинит случаи, где верная пара уже в топе по рангу |
| Кандидатов на статью | 1, затем 3 | 2 | Одного мало: верная пара (0.476) проигрывала несвязанной (0.491) из-за случайных сущностей. 3 → 2: серая зона занимала 87% статей, офлайн-расчёт на 250 размеченных статьях дал −22% вызовов LLM ценой около 2 из 126 соединяемых пар |
| Порог слияния | только косинус | косинус + общая сущность большинства | Диапазоны косинуса у ложного слияния 26 статей Habr (0.70–0.88) и у корректных (0.69–0.94) пересекаются: поднять порог нельзя, не сломав рабочие кластеры; разделяют их сущности |
| Жаккар сущностей | обычный | с IDF-весами | Частые сущности («США», «МИД», «Россия») топили верную пару; AUC 0.9521 → 0.9676 |
| Пакетные запросы серой зоны (12 пар) | нет | написаны, **выключены** (`DEFAULT_GRAY_BATCH_SIZE = 1`) | Согласие с одиночными ответами 78.1% и 81.8% при требуемых ≥ 90% |

Подъём нижнего порога до 0.42–0.50 экономит вызовы, но теряет верные пары: при 0.42 соединяемых на 13% меньше, при 0.45 на 20%,
при 0.50 на 37%. Поэтому он не поднимался; снижать нагрузку решено ограничением числа кандидатов.

## Последствия

- **Качество (B-Cubed, 250 размеченных статей, 2026-10-14):** precision 0.927, recall 0.897 при пороге спецификации 0.8. Это
  измерение до правок P0 (сущности, лимиты, IDF) и до пересборки; новое полное измерение не выполнялось.
- Серая зона занимает около 87% статей (монитор, 2026-11-10) против порога тревоги 25% (в спецификации предполагалось около 10%).
  Это следствие калибровки, а не баг; решение о пороге тревоги за владельцем и не принято.
- Настройка держится на одной размеченной выборке из 250 статей: риск переобучения; веса сигналов не перекалибровывались.
- **Открытые проблемы** после пересборки событий за 7 суток (план P0, фаза 6, ручной просмотр 2026-11-16): 26 статей Habr склеены
  в «Claude Opus 5.5» через общие сущности про ИИ; «Израиль: выборы» (20 статей, 63 ч) и «Россия — Африка» (21 статья, 53 ч) объединяют
  несколько разных событий. Это старый бэклог, но критерий «каждое событие про одно» не выполнен. Предложено (P1): ограничение
  «из одного издания», штраф за совпадение метки времени, порог для ультракоротких пар.
- Кластеризация упирается в квоты LLM и эмбеддингов ([ADR-0008](0008-besplatnye-llm-i-fallback.md)): на 2026-11-16 оставались
  1726 статей без события и 3078 без эмбеддинга.
