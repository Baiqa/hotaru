# ADR-0001: Два процесса: воркер на Python отдельно, фронт только читает БД

**Статус:** Принято
**Дата:** 2026-09 (спецификация `CLAUDE.MD` §2)
**Принимал:** владелец проекта

## Контекст

Продукту нужны сбор статей (парсинг сайтов, браузерный рендеринг на старших уровнях лестницы), извлечение сущностей на spaCy,
обращения к LLM и кластеризация. Фронт должен быстро открываться и вести себя предсказуемо. По спецификации парсинг не
помещается в лимиты serverless-функций.

## Решение

Два независимых процесса, связанных только базой данных:

```
[Python-воркер] → [PostgreSQL] ← [Next.js]
 сбор, извлечение,   хранение     чтение, рендер
 кластеризация,
 генерация текстов
```

Фронт **никогда не ходит в LLM и не парсит сайты**: он читает готовые данные. Воркер ничего не отдаёт фронту напрямую.

## Рассмотренные варианты

| Вариант | Оценка |
|---|---|
| Всё внутри Next.js (API-маршруты и серверные задачи) | Отклонён в спецификации: парсинг и обработка не помещаются в лимиты serverless |
| Два процесса через общую БД | Выбран |

Другие варианты (очередь сообщений, отдельный API-сервис) в источниках не рассматривались. Спецификация относит очередь/крон к
«достаточно крон-задач воркера на старте».

## Последствия

- Проще: фронт быстрый и детерминированный; воркер можно перезапускать, останавливать и переносить независимо от сайта.
- Сложнее: два рантайма (Python 3.13 с `uv`, Node 20.9+), единственный контракт между ними — схема БД (см. [ERD](../erd.md)).
  Любое изменение схемы затрагивает обе стороны.
- Данные на сайте отстают от воркера на время его работы; свежесть сайта целиком зависит от того, запущен ли воркер
  (см. [ADR-0010](0010-hosting-besplatno.md)).
- Права: фронт читает анонимным ключом, воркер подключается напрямую владельцем таблиц ([ADR-0011](0011-dostup-k-dannym.md)).

## Проверка

В `web/src` нет клиентов LLM и парсеров. Единственное упоминание Gemini/Groq в коде фронта — подпись в блоке квот страницы
`/admin`.

## Источники

`CLAUDE.MD` §2 («Разделение на два процесса»), структура репозитория (`worker/`, `web/`).
