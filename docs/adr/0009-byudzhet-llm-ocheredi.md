# ADR-0009: Бюджет LLM: очереди, приоритеты, мягкий лимит времени шага

**Статус:** Принято, часть критериев не подтверждена
**Дата:** 2026-11-12 (план P0), 2026-11-16 (код)
**Принимал:** владелец проекта

## Контекст

Спрос около 2500–3000 вызовов LLM в сутки при квоте около 500 у Gemini и 450–570 у Groq ([ADR-0008](0008-besplatnye-llm-i-fallback.md)).
Очередь синтеза шла от старых событий к новым и не помечала неудачи: в её голове стояли события 2022–2023 годов; 83 из 92 готовых сводок
принадлежали одиночным событиям, у топ-30 главной сводок не было. Отдельная проблема: 19 из 20 отменённых запусков GitHub Actions упёрлись в
таймаут на одном медленном шаге, и остальные шаги не выполнялись.

## Решение

- **Очередь синтеза:** только формат `summary_30s`; сначала события с 2+ изданиями, затем по свежести; отсечка: последняя статья моложе 3 суток
  (`QUEUE_FRESH_DAYS = 3`); сводка пересоздаётся, если изданий стало больше; три неудачи подряд откладывают событие на сутки; потолок 10
  одиночных событий за запуск. Неудача = отклонена пост-проверка или мусорный ответ; квота и сеть неудачей не считаются.
- **Очередь фактов:** `hotaru-extract-claims --scope multi|rest|all --max-items N`, свежие первыми; счётчик попыток растёт только от
  постоянных ошибок запроса (4xx, кроме 429). Эмбеддинги и группировка фактов только для свежих событий с 2+ изданиями.
- **Денормализация:** `events.source_count`, `last_article_at` и другие поля обновляет триггер на `event_articles`, а не вызовы из кода
  (статьи входят в события и покидают их в четырёх местах воркера).
- **Мягкий бюджет времени шага** `--max-minutes N` (шаг сам завершает текущий элемент и выходит успешно, `stopped_by_time_budget`) плюс жёсткий
  `timeout-minutes` как страховка; редкие шаги по `--if-due-hours N` через журнал `pipeline_runs`; сбой одного шага не останавливает следующие.
- **Пакетные запросы** серой зоны и эмбеддингов подготовлены, но **выключены**: согласие пакетной серой зоны с одиночными ответами 78.1% и
  81.8% при требуемых ≥ 90%.

## Рассмотренные варианты

Платный тариф (отложен, [ADR-0008](0008-besplatnye-llm-i-fallback.md)); сокращение потока (источников или фильтр свежести), решение за
владельцем и не принято. Отдельный cron на редкие шаги заменён проверкой по журналу.

## Последствия

- Квота тратится на видимое: свежие многоисточниковые события первыми.
- Старые события (старше 3 суток) без текста уже не получат его автоматически.
- Критерии плана **не подтверждены**: «все свежие события с 2+ изданиями получают сводку за два запуска» и «доля серой зоны на статью упала
  минимум впятеро» (последнее невозможно, пока пакеты выключены).
- В SDK `google-genai` список строк для эмбеддинга склеивается в один вектор; для пакета нужен список объектов `Content` по одному на текст
  (найдено опытом, сам опыт на живой квоте не поставлен).
- Журнал запусков (`pipeline_runs`) и страница `/admin` делают расход видимым; остаток квот в БД не хранится, показывается оценка по журналу.
