# ADR-0010: Бесплатный хостинг: Vercel + Supabase + GitHub Actions

**Статус:** Принято; расписание Actions **отключено 2026-11-17**, обработка идёт локально
**Дата:** 2026-11-07 (решение), 2026-11-12 (единый workflow), 2026-11-17 (отключение расписания)
**Принимал:** владелец проекта

## Контекст

Хостинг воркера в спецификации (§8) был открытым вопросом. Бюджета нет. Репозиторий уже публичный; аудит истории перед публикацией показал, что
секретов в коммитах нет.

## Решение

| Часть | Где | Как |
|---|---|---|
| Фронт `web/` | Vercel Hobby | Root Directory = `web`, автодеплой из `master`; переменные `NEXT_PUBLIC_SUPABASE_*` |
| БД | Supabase, бесплатный тариф | Регулярные записи воркера не дают проекту уснуть |
| Воркер `worker/` | GitHub Actions по расписанию | Секреты репозитория: `DATABASE_URL`, `CONTACT_EMAIL`, `GOOGLE_API_KEY`, `GROQ_API_KEY` |

Первоначально четыре workflow (`collect`, `llm`, `maintenance-hourly`, `maintenance-daily`); с 2026-11-12 один `pipeline.yml`: все шаги по очереди
в одном job, поэтому параллельных писателей в БД нет по построению. Запуски только по расписанию и вручную, без `pull_request`: секреты не должны
попадать в код из форков публичного репозитория.

**2026-11-17:** `pipeline.yml` отключён (`gh workflow disable`, файлы не тронуты). Владелец решил, что свежесть новостей сейчас менее важна, чем разбор уже
собранного бэклога. Обработка идёт локально, шаг за шагом.

## Рассмотренные варианты

Источники фиксируют только: платный хостинг и VPS не выбраны («VPS позже»); перенос воркера на сервер с cron в P0 не входит. Планировщик «один workflow на
GitHub Actions» был выбран владельцем 2026-11-12.

## Последствия

- Проще: ноль затрат; публичный репозиторий даёт бесплатные минуты Actions.
- **Cron GitHub троттлится:** за около 20 ч collect сработал 5 раз вместо 40 по расписанию (llm 4 вместо 50, hourly 5 вместо 20); фактическая частота
  1 запуск в 2–19 часов. При потоке около 1100 статей в сутки и около 8 с на статью кластеризации 2–5 запусков в сутки не успевают: к 2026-11-17 остались
  около 4,4 тыс. статей без события. Это причина отключения расписания.
- Последствие отключения: **облачный конвейер ничего не собирает**; чтобы считать данные свежими, надо смотреть `pipeline_runs` или `/admin`.
- Логи публичных workflow видны всем: воркер не должен печатать лишнего.
- Vercel Hobby рассчитан на некоммерческое использование; запланированные workflow в публичных репозиториях могут отключаться после долгой неактивности
  (в плане хостинга назван срок около 60 дней, документация GitHub не перепроверялась).
- Хостинг воркера остаётся открытым вопросом (§8).

## Действия

1. [ ] Выбрать постоянное место для воркера (VPS или иное) после разбора бэклога.
2. [ ] Перед повторным включением Actions пересчитать бюджет времени шагов под реальный поток.

## Источники

Планы `hosting-besplatno.md`, `ci-ustoychivost-pajplajna.md` (в истории git), P0 (фаза 2); `.github/workflows/`; заметки проекта (решения 2026-11-07, статус
2026-11-17); `gh workflow list` (`pipeline: disabled_manually`).
